# 坑库 — pitfalls

按**阶段**组织，不按主题。因为坑的价值在于"我现在在哪个阶段，该防什么"。

每条格式固定：**现象 → 根因 → 修法 → 复现边界**。
新坑一律追加到对应阶段末尾，注明发现日期与 run-id。单文件写到 500 行以上再拆目录。

---

## A 阶段（设计定义）

### A-1 方案里留白，把判断推给建模者
- **现象**：`A-plan.md` 写"塔板数取 20–40 之间合适值"、"压力按常规设定"。
  modeler 现场瞎猜，失败后无法归因是设计错还是执行错。
- **根因**：把设计不确定性当成执行者的自由度。
- **修法**：方案里每个参数**必须是单一确定值**。不确定就给"取值 + 依据 + 若失败的备选值"，
  例如"塔板数 30（DSTWU 估 Nmin=14，取 2.1×Nmin）；若干板取 40"。
- **边界**：所有阶段。这是 A 阶段唯一的硬验收标准。

### A-2 单位换算被推迟到执行时
- **现象**：方案写"进料 100 kmol/hr, 25°C, 1.5 bar"，modeler 边建边换算，某处漏换。
- **根因**：换算发生在多个地方就一定会漏。
- **修法**：`A-plan.md` 所有参数**双列**：`工程单位 | SI 值`。modeler 只读 SI 列。
- **边界**：所有阶段。

### A-3 模拟目的没定，精细度失控
- **现象**：只要算个物料平衡，却上了严格塔 + 动力学反应器，收敛耗掉全部预算。
- **根因**：没有区分"物料平衡估算 / 方案比选 / 设计定型 / 现有装置标定"。
- **修法**：A 阶段第一句就写模拟目的，并据此定模块严格度上限。
  物料平衡估算允许全程用 SEP/RSTOIC 交付（结论分级 C）。
- **边界**：所有任务。

### A-4 忘了惰性组分与杂质
- **现象**：进料只写主组分，建完模型加循环后发现累积失控，或结果与实际差很多。
- **根因**：真实原料含 N2、水、轻重杂质，这些恰恰是循环累积和塔顶不凝气的主角。
- **修法**：A 阶段进料表必须有"杂质/惰性"行，即使含量很低也要列，并明确其去向
  （随哪个产品出、是否需要 purge）。
- **边界**：有循环、有不凝气的流程尤其致命。

### A-5 产品指标写成定性描述
- **现象**："高纯度乙醇"、"CO2 尽量回收"。D 阶段无法判定达标。
- **根因**：需求未量化。
- **修法**：每个指标必须是 `量 + 数值 + 基准（摩尔/质量）+ 允差`。
  甲方没给就用行业常规值并标注"假设"。
- **边界**：所有任务。

## B 阶段（骨架 / 物性 / 物料平衡）

### B-1 缺二元交互参数导致"全绿的错误结果"
- **现象**：所有 BLKSTAT=0，塔顶纯度轻松达标，但结果与实际/文献差很远。
- **根因**：活度系数模型缺该二元对参数时，Aspen **静默取 0 或用 UNIFAC 估算**，不报错。
- **修法**：见 `engineering-rules.md` §1.3。至少要把关键二元对列出来并标注确认状态。
- **边界**：所有用 NRTL/UNIQUAC/WILSON/ELECNRTL 的体系。**本库最贵的一条。**

### B-2 组分标签被截断后组成设不上
- **现象**：`set_stream_composition_batch` 报组分不存在，或某组分流量恒为 0。
- **根因**：组分名 > 8 字符被 Aspen 截断（PROPYLENE → PROPYLEN）。
- **修法**：`add_component()` 后立刻 `list_components()`，之后一律用返回的实际标签。
- **边界**：所有长名组分、离子组分。

### B-3 未 `set_unit_set("SI") + reinit_and_run()` 就建块
- **现象**：`Cannot create Blocks node`；或块建成了但 type 为空，运行直接失败。
- **根因**：COM 节点树未初始化。
- **修法**：`new_simulation()` 后固定三连。已经建错了要 `remove_block` 重建。
- **边界**：只在新建模拟时。`open_file` 打开已有文件不需要。

### B-4 共沸体系用了 EOS
- **现象**：塔顶纯度算到 99.9% 且很容易收敛，实际物理上不可能（乙醇-水共沸点 ~95.6 wt%）。
- **根因**：PENG-ROB 等 EOS 抓不住共沸，把难分离体系算成易分离。
- **修法**：极性体系一律活度系数模型。B 阶段用单个 FLASH2 做一次 T-x 抽查验证相平衡合理性。
- **边界**：含醇/水/酮/酸/胺的体系。

### B-5 物料不闭合但被当成"收敛了"
- **现象**：BLKSTAT 全 0，但 Σ入 ≠ Σ出。
- **根因**：有流股没连上（悬空），或分离模块的分割率之和不为 1。
- **修法**：B 阶段门禁就是闭合 ±0.5%。用 `flowsheet_topology()` 查悬空流股，
  `list_all_streams()` 对照产物清单。
- **边界**：所有流程。

### B-6 MIXER 出口压力取了最低入口压
- **现象**：混合后压力突降，下游泵/塔的压力剖面全乱。
- **根因**：MIXER 不设 PRES 时默认取所有入口的最低压力。
- **修法**：显式设 MIXER 的 PRES，或保证各入口压力一致。
- **边界**：任何多股汇合处。

## C 阶段（严格化 / 收敛）

### C-1 一次替换多个模块，失败后无法归因
- **现象**：把 3 个 SEP 同时换成 RADFRAC，跑不通，不知道是哪个塔的问题。
- **根因**：违反单变量原则。
- **修法**：一轮只严格化一个区。换完立刻 `reinit_and_run()` + `block_status()`，
  通过了再动下一个。归因表逐轮记录。
- **边界**：L2/L3 流程。

### C-2 用 `reinit_and_run()` 丢掉了好初值
- **现象**：上一轮辛苦收敛的结果，改一个小参数后 reinit 重跑又不收敛了。
- **根因**：`reinit_and_run()` 清空结果，从冷启动开始。
- **修法**：**区分两种意图**——
  改结构/规格后必须 `reinit_and_run()`（避免残留初值造成假收敛）；
  想继承上一轮收敛结果做小步推进时用 `run()`。
  D 阶段小步逼近规格时尤其要用 `run()`。
- **边界**：C/D 阶段。这条与 mcp-playbook §1.6 是一对，注意别混。

### C-3 tear 点估值给错了对象
- **现象**：`set_tear_estimate("MIXED", ...)` 之类，写给了不存在或非 tear 的流股，无效果。
- **根因**：凭想象指定 tear 流股名。
- **修法**：**必须先 `list_tear_streams()`**，只对返回的流股名给估值。
  估值要物理合理（不能是 0），T/P/流量三项都给。
- **边界**：所有有循环的流程。

### C-4 循环一上手就闭合
- **现象**：加上循环流股后从来没收敛过，且不知道非循环部分是否本来就有问题。
- **根因**：把两类不确定性（结构/参数 vs 循环收敛）叠在一起。
- **修法**：B 阶段先断环 —— 循环流股改成**固定组成的假进料**（按物料平衡估算），
  跑通全流程。C 阶段末再接回循环，用断环时的假进料值作 tear 估值。
- **边界**：L3 流程强制。

### C-5 塔干板（COLUMN DRIES UP）
- **现象**：RADFRAC 报某级无液相。
- **根因**：多数是两个规格互相冲突（如 rr 太小同时 d 太大），或进料级选在塔顶/塔底。
- **修法**：优先放宽规格 → 调进料级到中部 → 加塔板数 → 最后才怀疑物性。
  用 DSTWU 先估合理 rr / N / 进料级再回填。
- **边界**：RADFRAC / EXTRACT。

### C-6 `run()` 30 秒超时被误判为发散
- **现象**：run 返回超时，误以为流程有错，去乱改参数。
- **根因**：大循环/多塔流程本来就算得慢。
- **修法**：先 `batch_refresh(off)` 关 GUI 刷新，再用 `run_async()` + 轮询 `status()`。
  确认是真发散再改参数。
- **边界**：L3 流程、多塔流程。

### C-7 压力倒挂
- **现象**：模拟"收敛"了但某段下游压力高于上游且中间没有增压设备。
- **根因**：各块的 PRES 是独立设的，没人检查剖面连续性。
- **修法**：designer 在 A 阶段给**完整压力剖面表**（每个节点一个压力值），
  modeler 照抄。`simulation_warnings()` 能抓一部分。
- **边界**：所有流程。E 阶段第 5 条校核。

## D 阶段（规格达标）

### D-1 规格物理不可达却硬调参数
- **现象**：为了让塔顶乙醇达 99.5 mol%，把塔板数加到 200、回流比调到 50，
  预算耗尽仍不达标。
- **根因**：乙醇-水在常压有共沸（~89.4 mol%），普通精馏物理上到不了 99.5%。
  这是**方案问题**，不是调参问题。
- **修法**：D 阶段第一步先判**可达性上限**（共沸组成、相对挥发度、平衡限制），
  确认不可达就返回 `NEEDS_DESIGN_CHANGE`，建议共沸精馏/变压精馏/分子筛，
  **不要继续调参**。
- **边界**：所有含共沸、平衡限制、反应转化率上限的指标。**D 阶段最重要的一条。**

### D-2 MCP 没有 Design Spec，用错了绕行顺序
- **现象**：直接去 COM 构造 Design-Spec 节点，反复失败，浪费预算。
- **根因**：选了风险最高的路径。
- **修法**：按 `mcp-playbook.md` §5 的优先级：
  ① `sensitivity` 扫描 + 插值逼近（无副作用，最稳）
  ② `set_value` 写 RadFrac 塔内规格
  ③ COM 构造外层 Design Spec（未实测，最多试 2 次）
- **边界**：所有需要"给定指标反求参数"的场景。

### D-3 多个指标同时调，互相打架
- **现象**：调回流比让塔顶达标，塔底又超标；来回震荡。
- **根因**：自由度不够（2 个规格位置塞 3 个目标），或两个目标本身冲突。
- **修法**：先数自由度。RADFRAC 只有 2 个规格位。目标多于自由度时，
  必须增加设计变量（加塔板、改压力、加侧线）——这是**设计变更**，返回 designer。
- **边界**：RADFRAC 及所有规格数固定的模块。

## E 阶段（校核 / 交付）

### E-1 建模者自审通过
- **现象**：modeler 说"结果合理"，交付后被工程师发现温度交叉。
- **根因**：生产者审自己的产物，会为了通过而放宽判据。
- **修法**：E 阶段必须派 `aspen-checker`（独立实例、只读），
  逐条走 `engineering-rules.md` §4 的 12 条并给量化结果。
- **边界**：所有任务。

### E-2 把 BLKSTAT=0 当作交付标准
- **现象**：报告只写"全部收敛"。
- **根因**：混淆"算出来了"和"算对了"。
- **修法**：报告必须含 12 条校核的量化结果 + 结论可用性分级（A/B/C/D）。
- **边界**：所有任务。

### E-3 循环里惰性组分无界累积却没人看
- **现象**：循环流股中 N2 摩尔分数达到 40%，但模拟"收敛"了。
- **根因**：分离模块把某组分设成 100% 分离，或流程缺 purge。
- **修法**：E 阶段第 9 条校核 —— 读循环流股组成，看惰性组分是否异常高。
  异常则回溯到设计：需要加 purge 支路（`NEEDS_DESIGN_CHANGE`）。
- **边界**：所有含循环的流程。

### E-4 失败了却没留下接管包
- **现象**：预算耗尽，只留一句"未能收敛"，工程师还得从零开始。
- **根因**：没有把失败过程物化。
- **修法**：任何非成功结局都必须产出 `HANDOVER.md`（含完整归因表）。
  **这是本系统的核心交付物**，比模型文件更值钱。
- **边界**：所有任务。

### E-5 `.rep` 报告整份读进上下文
- **现象**：`export_report_file` 后 Read 整个文件，上下文瞬间爆掉。
- **根因**：Aspen 报告文件可达数 MB。
- **修法**：只用 Grep 按关键词抽取需要的段落。
- **边界**：checker。

## 跨阶段（编排机制层面）

### X-1 主 agent 自己调了 aspen MCP
- **现象**：主 agent 上下文里塞满 COM 树输出和 Aspen 报错，几轮后开始遗忘早期决策。
- **根因**：图省事，觉得"就查一下状态"。
- **修法**：主 agent 一律不碰 aspen-plus。要看状态就派 subagent 回执。
- **边界**：始终。

### X-2 派发 prompt 里写"按刚才说的做"
- **现象**：subagent 答非所问或从零重做。
- **根因**：subagent **不继承对话历史**。
- **修法**：派发 prompt 必须自包含：把上一阶段回执的原始报错、参数值、
  文件绝对路径**整段复制**进去。
- **边界**：始终。

### X-3 并行派发触碰 MCP 的 subagent
- **现象**：两个 subagent 同时操作，模型内容互相覆盖，状态错乱。
- **根因**：Aspen 是单实例单文件的 COM 会话。
- **修法**：触碰 aspen-plus 的派发**严格串行**。只有纯文档工作可并行。
- **边界**：始终。

### X-4 无限试错，预算失控
- **现象**：C 阶段改了 15 轮参数，上下文爆掉，无成果。
- **根因**：没有硬预算，也没有升级路径。
- **修法**：B ≤2 / C ≤5 / D ≤4 轮，跨阶段回退 ≤2 次。超限即出 `HANDOVER.md`。
- **边界**：始终。

### X-5 交棒时没 save，下一个 agent 打开的是旧状态
- **现象**：modeler 的成果丢失，checker 校核的是上一版模型。
- **根因**：Aspen 内存状态未落盘。
- **修法**：每次 subagent 结束前必须 `save()`，并把绝对路径写进 `state.json.apw_path`；
  下一个 subagent 开头 `status()` 确认打开的是同一个文件。
- **边界**：始终。

### X-6 `.ps1` 里写中文 / here-string，PowerShell 5.1 解析失败
- **现象**：`new-run.ps1` 报「一元运算符"-"后面缺少表达式」「字符串缺少终止符」，
  而肉眼看语法完全正确。
- **根因**：文件工具写出的是 **UTF-8 无 BOM**，Windows PowerShell 5.1 按当前代码页
  （GBK）解码 `.ps1`，中文字符被打散，here-string 的终止符 `"@` 也一起失效。
- **修法**：**脚本文件一律只写 ASCII**（英文注释与提示），所有中文内容放进
  `templates/` 下的 `.md`，脚本用 `Copy-Item` + 按行号打补丁。读写 `.md` 时显式带
  `-Encoding UTF8`。
- **边界**：所有 `.ps1`。（v0.1 搭建期实测）

### X-7 控制台显示乱码被误判为文件损坏
- **现象**：`Get-Content xxx.md` 输出一堆乱码方块，以为文件写坏了。
- **根因**：只是控制台代码页与 UTF-8 不符，**文件本身是好的**。
- **修法**：用 Read 工具核验文件内容，不要靠控制台输出判断编码是否正确。
- **边界**：所有中文 `.md`。
